# OpenRag 未完成项与与 PRD 的差距

本文档汇总当前代码库中**尚未实现**或**仅部分实现**的能力，以及与 `openrag/prd.md` 描述的对照，便于排期与验收。实现状态以仓库内实际代码为准；若已有变更，请同步更新本节。

---

## 1. 与 PRD「查询流程」的差距

### 1.1 意图与路由（PRD §2.1）

| 项 | 状态 | 说明 |
|----|------|------|
| 检索策略分流（轻量 / 深度 / 精准等） | **部分** | 已有 `retrieval_strategy`（`auto|light|deep|precise|flat`）及规则推断 `query_intent.py`（B5）。 |
| LLM 做意图分类 | **未** | 当前为关键词与启发式规则，非大模型意图路由。 |

### 1.2 L1「导航层」（PRD §2.3）

| 项 | 状态 | 说明 |
|----|------|------|
| L1 向量召回 | **有** | `MilvusLayerStore` + 上下文检索融合。 |
| LLM 根据 L1 选择 L2 片段 | **部分** | `l1_llm_navigator.py`：可选 `use_l1_llm_navigation`，用 LLM 输出 chunk 下标并过滤向量命中；需 `OPENAI_API_KEY`。 |
| 「是否深入该目录 / 子文件」的逐步决策 | **未** | 无独立状态机式目录导航；范围主要靠 L0/L1 向量与候选 `file_id`。 |

### 1.3 L2 与融合（PRD §2.4）

| 项 | 状态 | 说明 |
|----|------|------|
| 不全文加载、候选内切片召回 | **有** | 上下文模式下先 L0→L1 再限定 `file_ids` 搜 chunks；可选 LLM 再过滤。 |
| 仅加载「L1 导航指定」的切片（严格语义） | **部分** | 启用 LLM 导航时近似；未启用时仍为向量 Top-K。 |

### 1.4 PRD §2.5

| 项 | 状态 | 说明 |
|----|------|------|
| 正文 | **空** | `prd.md` 中 2.5 无具体需求条目，待产品补全。 |
