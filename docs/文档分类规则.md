# 文档分类规则

本文档用于将 `E:\外汇文件_filter_分组` 下的外汇、债券、衍生品等业务文件划分为三类：

- `manual`：手册、指南类
- `laws`：法则、规范类
- `general`：普通类型

分类时不只看文件名关键词，而是综合判断“正文用途 + 文件名信号 + 正文结构”。尤其要避免把带有“操作”的制度类文件误判为 `manual`。

## 总体原则

优先判断文档的主要用途：

- 如果文档主要在教用户“怎么做”，归为 `manual`。
- 如果文档主要在规定制度、规则、义务、适用范围、业务边界或标准条款，归为 `laws`。
- 如果文档主要是介绍、表单、清单、新闻、材料或一般说明，归为 `general`。

冲突时建议优先级为：

```text
laws > manual > general
```

原因是法规、规则类文档中也可能出现“操作、流程、申请”等词，但这类文档更需要保留条款结构；普通指南中通常不会大量出现“第一条、应当、不得、本规则”等规范性表达。

## manual：手册、指南类

`manual` 的核心标准是：文档主要在教用户或机构“如何完成某项操作或办理某项业务”。

典型文件名信号：

- `手册`
- `指南`
- `快速使用指南`
- `入市指南`
- `开户流程`
- `联网开户`
- `配置要求`
- `操作手册`
- `投资者问答`

典型正文信号：

- 大量出现操作动作：`登录`、`点击`、`选择`、`填写`、`提交`、`下载`、`安装`、`配置`、`菜单`、`客户端`、`系统界面`
- 结构偏流程型：`第一步`、`第二步`、`一、开户准备`、`二、系统登录`、`三、提交材料`
- 面向用户、投资者、机构说明办理路径，而不是规定权利义务

典型例子：

- 操作手册
- 入市指南
- 联网和开户流程指南
- 系统配置要求
- 快速使用指南
- 以办理流程为主的投资者问答

注意：`操作规程`、`操作细则` 不直接归为 `manual`，应优先按 `laws` 判断。

## laws：法则、规范类

`laws` 的核心标准是：文档主要在规定制度、规则、义务、适用范围、业务边界、交易流程约束或标准条款。

典型文件名信号：

- `规则`
- `规程`
- `细则`
- `办法`
- `规范`
- `协议`
- `条款`
- `制度`
- `准入指引`
- `交易规则`
- `业务规范`
- `技术规范`
- `数据规范`
- `服务协议`

典型正文信号：

- 有法条结构：`第一条`、`第二条`、`总则`、`附则`、`第一章`、`第二章`
- 使用规范性表达：`应当`、`不得`、`适用于`、`本规则`、`本办法`、`本规范`、`本协议`、`中心负责`
- 描述业务准入、交易确认、清算结算、交易员管理、数据接口、服务边界、违约责任等制度性内容

典型例子：

- 交易规则
- 操作规程
- 操作细则
- 管理办法
- 业务规范
- 技术规范
- 数据规范
- 服务协议
- 标准条款
- 关于发布、修订、调整某规则/办法/细则/规范的通知

注意：文件名里包含“指引”时需要结合内容判断。如果主要规定准入条件、职责、适用范围和制度边界，归为 `laws`；如果主要说明办理步骤，归为 `manual`。

## general：普通类型

`general` 的核心标准是：文档既不是操作指导，也不是制度规范，主要是介绍、材料、表单、清单、新闻或一般说明。

典型文件名信号：

- `服务介绍`
- `产品介绍`
- `日历`
- `清单`
- `要素表`
- `信息表`
- `申请表`
- `变更表`
- `名单`
- `材料清单`
- `说明`

典型正文信号：

- 以说明性、展示性、表格型内容为主
- 没有明显步骤指导
- 没有明显 `第一条`、`应当`、`不得`、`本规则` 等制度条款
- 新闻稿、市场动态、发布信息类内容，除非正文是在正式发布某个规则、办法、细则或规范

典型例子：

- 服务介绍
- 产品介绍
- 衍生品交易冲销日历
- 业务申请表
- 信息变更表
- 合约要素表
- 材料清单
- 市场新闻或普通公告

## 冲突处理口径

遇到多重信号时，按以下规则处理：

- `操作规程`、`操作细则`：归 `laws`
- `入市指南`、`开户指南`、`快速使用指南`：归 `manual`
- `准入指引`：规定准入条件和制度边界时归 `laws`；说明办理流程时归 `manual`
- `通知`：发布、修订、调整规则/办法/细则/规范的通知归 `laws`；普通公告、新闻或动态归 `general`
- `申请表`、`信息表`、`要素表`、`材料清单`：默认归 `general`
- `服务介绍`、`产品介绍`：默认归 `general`
- `投资者问答`：如果回答“怎么申请、怎么操作”，归 `manual`；如果只是政策解读或市场介绍，归 `general`
- 文件名和正文冲突时，以正文主要用途为准

## 建议的批量分类输出字段

后续对所有文件执行分类时，建议输出以下字段：

- `文件路径`
- `分类`：`manual`、`laws` 或 `general`
- `置信度`：高 / 中 / 低
- `命中依据`：简述命中的文件名、标题、正文结构或关键词依据
- `是否需要人工复核`
- `复核原因`：例如正文抽取为空、文件名信号冲突、扫描 PDF、旧版 `.doc` 解析失败等

## 低置信度场景

以下情况应标记为需要人工复核：

- 扫描版 PDF，无法稳定抽取正文
- 旧版 `.doc` 文件正文抽取失败
- 文件名同时出现 `指南/指引` 和 `规则/规程/细则/办法`
- 文件名为附件，缺少主文件上下文
- 正文很短，只包含表格、签章页或封面
- 文件名和正文用途明显冲突

## 分类执行输出规则

执行本文档分类规则后，应生成分类结果文件，不应直接修改、移动、重命名或删除原始文件。

分类执行的标准产物包括：

- 逐文件分类明细 CSV
- 分类汇总 Markdown 报告

建议输出路径如下：

- `docs/eval/foreign_exchange_document_classification.csv`
- `docs/eval/foreign_exchange_document_classification_summary.md`

### 逐文件分类明细

逐文件分类明细用于记录每个文件的分类结果和判断依据。每个原始文件应对应一行记录。

CSV 文件必须包含以下字段：

- `文件路径`：原始文件完整路径
- `文件名`：原始文件名
- `分类`：只能是 `manual`、`laws` 或 `general`
- `置信度`：高 / 中 / 低
- `命中依据`：说明该文件被分到对应类别的主要原因
- `是否需要人工复核`：是 / 否
- `复核原因`：需要人工复核时填写，例如正文抽取失败、文件名信号冲突、扫描 PDF、旧版 `.doc` 解析失败等

示例：

```csv
文件路径,文件名,分类,置信度,命中依据,是否需要人工复核,复核原因
E:\外汇文件_filter_分组\group_01\代理交易客户端(境外机构版)操作手册.pdf,代理交易客户端(境外机构版)操作手册.pdf,manual,高,文件名命中“操作手册”，正文偏系统操作说明,否,
E:\外汇文件_filter_分组\group_01\《银行间外汇市场交易确认技术规范》.pdf,《银行间外汇市场交易确认技术规范》.pdf,laws,高,文件名命中“技术规范”，属于制度/标准类文档,否,
E:\外汇文件_filter_分组\group_01\服务和标准_服务介绍.md,服务和标准_服务介绍.md,general,高,文件名命中“服务介绍”，内容为一般介绍,否,
```

### 分类汇总报告

分类汇总 Markdown 报告用于快速查看整体分类结果和需要人工复核的文件。

汇总报告应至少包含以下内容：

- 总文件数
- `manual` 文件数量和占比
- `laws` 文件数量和占比
- `general` 文件数量和占比
- 高 / 中 / 低置信度数量
- 需要人工复核的文件数量
- 需要人工复核的文件列表
- 低置信度文件列表
- 分类规则版本或执行时间

### 结果使用约束

分类结果只作为后续解析策略选择、评测分层、人工复核和导入配置的依据。

在没有人工确认前，低置信度结果不应作为最终文档体裁标签直接写回生产数据。
