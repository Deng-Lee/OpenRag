# OpenRag 使用说明（Web 与配置）

> 与 [01-项目说明.md](./01-项目说明.md)、[02-Kubernetes部署.md](./02-Kubernetes部署.md)、[04-外部系统接入与API.md](./04-外部系统接入与API.md) 为同一套四份说明文档。本地起服务、Docker Compose 详见仓库根目录 `LOCAL_DEV_GUIDE.md` 与 `docker/README.md`。

## 1. 访问与登录

1. 打开部署地址（本地开发默认前端端口见 `web/vite.config.ts`；Docker 生产默认 `http://localhost`）。
2. **注册**：使用 `/register` 创建账号（若部署方关闭注册，需由管理员在库内创建用户）。
3. **登录**：成功后前端将 JWT 存入 `localStorage`，后续请求自动携带 `Authorization: Bearer <token>`。

## 2. 页面与路由

| 路径 | 说明 | 可见性 |
|------|------|--------|
| `/files` | 工作区文件树、上传、预览、触发解析相关操作 | 已登录 |
| `/search` | 语义检索、结果与分块上下文预览 | 已登录 |
| `/tasks` | 解析与异步任务列表 | 已登录 |
| `/permissions` | 当前账号在各工作区的 **读/写** 权限及来源（角色名 vs 单独授权） | 已登录 |
| `/settings` | 个人资料、退出登录 | 已登录 |
| `/service-tokens` | 为指定工作区创建/吊销 **服务令牌**（`sk-...`） | **系统管理员**（`is_admin`） |
| `/admin-permissions` | 角色定义、工作区授权、用户-角色绑定等管理 | **系统管理员** |

非管理员访问管理页会被重定向到 `/files`。

## 3. 权限隔离模型（概念）

- **工作区（Workspace）**：数据与文件的边界；检索与列表均在「当前工作区」上下文中执行。
- **成员权限**：用户对工作区可有读、写等能力（具体以 API 与数据库模型为准）。
- **角色（Role）**：管理员可定义角色，并将多个工作区的读写能力绑定到角色；再将角色授予用户。用户最终在「权限」页看到合并后的结果及来源说明。
- **服务令牌**：绑定 **单个** 工作区，权限为 `read` 或 `write`，仅供 `/service/v1` 机读接口使用，**不**替代用户 JWT。

> 实现细节与表结构以迁移脚本与 OpenAPI 为准；若与内网 LDAP 等集成，需自行扩展认证层。

## 4. 前端配置（`web/.env`）

从 `web/.env.example` 复制：

```bash
cd web
cp .env.example .env
```

| 变量 | 含义 |
|------|------|
| `VITE_API_URL` | 后端根 URL。开发默认 `http://localhost:8001`（与 `vite.config.ts` 中代理目标一致）；若希望与生产一致走同源 `/api`，可设为 `/api` 并依赖 Vite 代理 |

**开发服务器端口**：以 `web/vite.config.ts` 的 `server.port` 为准（当前默认为 **3000**）。

## 5. 后端与基础设施配置（摘要）

- **本地**：`OpenRag/.env`，键名见 `OpenRag/.env.example`（`POSTGRES_*`、`MILVUS_*`、`STORAGE_*`、`ELASTICSEARCH__*`、`SECRET_KEY` 等）。
- **Docker 生产**：`docker/.env`，与 `docker-compose.prod.yml` 中变量对应。

启用 Elasticsearch 全文能力时，需同时：

- 将 `ELASTICSEARCH__ENABLED` 设为 `true`
- 保证 `ELASTICSEARCH__HOSTS` 可达（Compose 内通常为 `http://elasticsearch:9200`）

并确保 **Task Worker** 已运行，否则上传后解析任务无法完成。

## 6. 常见操作提示

- **上传后无向量/检索为空**：在「任务」页查看失败原因；检查 Worker 日志、Embedding API Key、Milvus/ES 健康状态。
- **403 / 无工作区**：确认已被加入工作区成员，或已被授予角色/单独权限（管理员在「管理权限」中配置）。
- **管理员创建服务令牌**：在「服务令牌」页选择工作区与 `read`/`write`；密钥仅在创建时完整展示，请安全保存。机读调用方式见 [04-外部系统接入与API.md](./04-外部系统接入与API.md)。
